= authn
:toc: left
:toclevels: 2
:source-highlighter: rouge

Briques d'authentification pour Crystal, liées à aucun framework web.

Anciennement `kemal-auth`. Le nom était faux : rien dedans n'a jamais dépendu
de Kemal — `shard.yml` ne l'a jamais déclaré, et `Session` échange des
`HTTP::Cookie` de la bibliothèque standard, pas le contexte de requête d'un
framework. Le nom dissuadait simplement d'y recourir ailleurs.

link:README.adoc[English version]

== Fonctionnalités

[cols="1,3"]
|===
| Module | Description

| `Authn::Password`
| Hachage et validation BCrypt des mots de passe avec règles conformes CNIL (12+ caractères, majuscule, minuscule, chiffre, caractère spécial)

| `Authn::Token`
| Génération et vérification de tokens JWT

| `Authn::Session`
| Gestion des sessions via cookies HTTP, indépendante du framework

| `Authn::SmtpConfig`
| Configuration du serveur SMTP (paramétrable)

| `Authn::PasswordReset`
| Récupération de mot de passe par courriel

| `Authn::UserManager`
| Gestion des utilisateurs et invitations
|===

== Installation

Ajouter dans votre `shard.yml` :

[source,yaml]
----
dependencies:
  authn:
    github: aloli-crystal/authn
    version: "~> 0.1"
----

Puis exécuter :

[source,bash]
----
shards install
----

== Configuration SMTP

La configuration SMTP peut être fournie de trois manières, par ordre de priorité :

=== 1. À l'instanciation (priorité maximale)

[source,crystal]
----
smtp = Authn::SmtpConfig.new(
  host: "smtp.example.com",
  port: 587,
  username: "user@example.com",
  password: "secret",
  from_address: "noreply@example.com",
  from_name: "Mon Application",
  use_starttls: true
)
----

=== 2. Depuis un Hash (ex. : base de données)

[source,crystal]
----
smtp = Authn::SmtpConfig.from_hash({
  "smtp_host"         => "smtp.example.com",
  "smtp_port"         => "587",
  "smtp_username"     => "user@example.com",
  "smtp_password"     => "secret",
  "smtp_from_address" => "noreply@example.com",
  "smtp_from_name"    => "Mon Application"
})
----

=== 3. Via variables d'environnement (valeurs par défaut)

[cols="1,2,1"]
|===
| Variable | Description | Défaut

| `SMTP_HOST`
| Hôte du serveur SMTP
| `localhost`

| `SMTP_PORT`
| Port SMTP
| `587`

| `SMTP_USERNAME`
| Nom d'utilisateur
| _(vide)_

| `SMTP_PASSWORD`
| Mot de passe
| _(vide)_

| `SMTP_FROM_ADDRESS`
| Adresse d'expédition
| `noreply@example.com`

| `SMTP_FROM_NAME`
| Nom d'expéditeur
| `Mon Application`

| `SMTP_TLS`
| Activer TLS/SMTPS
| `false`

| `SMTP_STARTTLS`
| Activer STARTTLS
| `true`
|===

== Utilisation

=== Gestion des mots de passe

[source,crystal]
----
require "authn"

hash = Authn::Password.hash("MonMotDePasse1!")
Authn::Password.verify("MonMotDePasse1!", hash) # => true

errors = Authn::Password.validate("faible")
# => ["Le mot de passe doit contenir au moins 12 caractères.", ...]
----

=== Tokens JWT

[source,crystal]
----
token = Authn::Token.generate(
  secret: ENV["SESSION_SECRET"],
  sub: "1",
  email: "user@example.com",
  role: "admin"
)
payload = Authn::Token.decode(token, ENV["SESSION_SECRET"])
----

=== Récupération de mot de passe

[source,crystal]
----
smtp = Authn::SmtpConfig.new(host: "smtp.example.com", ...)
result = Authn::PasswordReset.send_reset_email(
  email: "user@example.com",
  reset_url: "https://monapplication.fr/reset-password",
  secret: ENV["SESSION_SECRET"],
  smtp: smtp
)
----

=== Gestion des utilisateurs

[source,crystal]
----
# Valider les champs propres d'un utilisateur — adresse, nom, rôle — revient à
# votre application : elle possède la formulation, les langues et la liste des
# rôles.
Authn::UserManager.send_invitation_email(
  email: "nouveau@example.com", prenom: "Marie",
  invitation_url: "https://monapplication.fr/set-password",
  secret: ENV["SESSION_SECRET"], smtp: smtp
)
temp_pwd = Authn::UserManager.generate_temp_password
----
